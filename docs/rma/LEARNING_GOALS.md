# 从能运行到能解释和修改

这个项目用于学习限定平地条件下的速度指令跟踪、RMA 历史适应和仿真部署验证。
当前结果主要覆盖前进指令，不能据此声称已完成转向、倒退、导航、复杂地形或真机部署。
1000 个 0.02 s 控制步是约 20 秒的评估窗口；它不意味着只能跑 20 秒，也不证明能无限稳定运行。

## 项目里的控制问题

上层给出机体系速度指令 vx/vy/wz；当前主要测试 vx，训练中的 vy/wz 固定为 0。
学生根据 IMU/关节状态等本体观测和历史产生 12 个关节目标偏移，PD 层实现执行。
教师在训练时额外使用摩擦和负载参数；部署图没有教师编码器或 Critic。
视觉用于感知地形/障碍、选择落脚或导航，是上层感知与决策的另一层；当前盲走低层策略没有视觉输入。
未来要让策略使用图像或地形信息，需要新增感知/观测设计并相应训练，不能把相机接上就期待当前网络自动理解。

## 学习要用产出来验收

| 能力 | 自己完成的最小产出 |
| --- | --- |
| PD 与动作语义 | 手算一关节两步更新；说明 action、目标角度和力矩的不同 |
| 观测与 reset | 从源码列出 49 维观测；说明 50 步历史如何填零及何时清空 |
| PPO | 手写一个小环境的 rollout/return/GAE，再解释 ratio、clip、value loss；不是先背完整框架 |
| RMA | 画出 teacher/student 图；指出学生训练中哪些参数冻结、MSE 监督目标来自哪里 |
| 实验设计 | 自己写假设与单变量 YAML，检查解析差异，用速度/RMSE/终止证据支持或否定假设 |
| 仿真迁移与部署 | 说明关节顺序、单位、缩放、周期和延迟为什么必须一致；解释数值一致与运动成功的区别 |

会运行命令、会读 loss，并不自动等于会实现 PPO 或独立设计控制器。
AI 可辅助编写和验证，但自己的贡献应按真实完成范围记录，不把辅助生成代码表述为独立提出的新算法。

## 从 EXP-012 开始，每轮当场复盘

1. 改前：用自己的话写问题、预测方向、唯一变量、固定项和通过标准。
2. 改时：亲自找到并理解一处配置或函数，能说明从 CLI 到环境的调用路径。
3. 跑后：自己读一张图和一份逐步 CSV；先写三句话，再核对工具给出的解释。
4. 每个阶段结束：关掉参考代码重写一个最小例子，定位不会的部分，再补 Python、控制或 RL 基础。

需要阶段复盘，但不等到项目全部完成。近期先学透单关节 PD、观测/动作/奖励、PPO 的一次数据采集与更新，再逐步接手实验代码。
真机阶段还要验证状态估计、传感器/执行器校准、单位与关节映射、时延、力矩/速度限制、故障与急停处理；纯仿真结果没有替代这些工程工作。
